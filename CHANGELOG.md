## 2026-10-19

### Fixed

- A model-supplied purpose class can no longer reach authority evaluation (bead hermes-agora-njy): CREATE_INTENT's purpose_class was format-checked only, yet it flows into UseAuthorization matching (evaluation and view admission) — an authorization granting resource R to purpose class 'research' was satisfied by the model simply claiming that class at intent creation, where every other authority input is runtime-minted. The handoff's rule is now implemented: purpose classes are bounded strings from the fixture registry, used to MATCH an existing permission, never evidence for issuing one. The manifest gains a `registries.purpose_classes` section (parsed and validated like the other registry sections), wired at runtime into the coordinator's `TurnConfig.purpose_classes` together with the always-registered mechanical class the runtime itself mints — a model CREATE_INTENT claiming an unregistered class is a typed POLICY_FORBIDDEN hold that completes the work with no intent grounded. The discretion spec documents the vocabulary bound and the new scenario. 346 passed / 0 skipped via 'uv run pytest'; ruff/format/ty clean.

- Submit-path writes are now crash-atomic (bead hermes-agora-yps): a plan submission's rendered payloads, effect records, the plan, and the submissions_used counter commit as ONE core transaction, so a crash mid-submit can no longer leave orphan effect/plan rows beside an un-incremented counter — the state whose same-revision re-derivation with a new created_at raised RecordConflictError on every restart (a crash loop). Rendering and validation now happen in a pure build phase before any write, so a bad effect can no longer strand the writes of its earlier siblings. The turn's terminal writes (the coordinator-minted admission/reject decisions, the fixed-id outcome:{work} record, and the work completion UPDATE) commit as one unit for the same reason. The mechanical and model-driven intent mints fold their payload + fragment + intent into one transaction each (a crash between the old commits orphaned the fixed-id fragment and the recovery re-mint surfaced a spurious CONFLICT hold). Three DURING_* crash checkpoints name the new windows for the fault injector, each with a restart-recovery regression that also asserts payload rollback and advances the virtual clock across the restart (so re-derivation cannot ride the byte-identical dedup path); `Coordinator.bootstrap` is idempotent on a reopened store and raises a typed error when the identity exists but the destination's fixtures do not. GLM-flash review applied (0 critical/high; both mediums were mutation-confirmed test-strength gaps — payload asserts and the unexercised clock advance — now fixed; the pre-crash audit-loss window remains known and accepted, audit rows are never re-derived). 342 passed / 0 skipped via 'uv run pytest'; ruff/format/ty clean.

- Coordinator hardening from the first whole-file adversarial review of the turn engine (0 critical, 2 high, 4 medium, 6 low, 2 nit — all four fixable-now findings fixed with regressions, the contract-level deviations filed as beads): a direct SUBMIT_PLAN(DEFER) resolution is now honored like FINISH(DEFER) — the intent gets its due time and the turn ends DEFERRED instead of silently swallowing the gate's DEFERRED decision; model-reachable access-request fields that fail the record contract (a list resource_id, id-hostile request ids) and CREATE_INTENT id collisions are typed INVALID_SCHEMA/CONFLICT holds that complete the work — never an uncaught exception stranding it RUNNING with a live lease — and intent stems are uniquified per creation so the same goal text can ground a second intent; a dispatch ending UNKNOWN reports the turn as DELIVERY_UNKNOWN (previously dead vocabulary misreporting a possibly-delivered effect as COMMITTED), and a reasonless FAILED_INTERNAL no longer audits as budget exhaustion (no audit row rather than a dishonest one). Also parenthesized a PEP 758 two-name except clause whose unparenthesized form masked a latent NameError-on-rename hazard. The defer/wake resume semantics, submit-path crash atomicity, dead HOLD work state, and the model-supplied purpose_class authority leak are filed as designed follow-ups (hermes-agora-9xk, yps, lcc, njy, xek). 339 passed / 0 skipped via 'uv run pytest'; ruff/format/ty clean.

## 2026-10-18

### Added

- Revocation cascades through transform chains and the dependency-edge writes are atomic (beads hermes-agora-5e2, resolving the design questions filed during the l34 review): `request_access` records the PRODUCER_INPUT edge from each transform output view to its granted source IN THE SAME TRANSACTION as its record batch, so `revoke_view` withdraws the whole derived chain (I14 "late derivations"), invalidates snapshots that admitted anything in it, and stales retained output memories — the scope index stops serving the withdrawn data, exactly the "not just search indices" I14 names. The production cascade edge itself is pinned by assertion in the transform request test. ## 2026-10-17

### Added

- View revocation now propagates to snapshot invalidation (beads hermes-agora-l34, closing the I14 gap filed during the M3 review): `ContextMemory.revoke_view` writes the view's revoked revision and invalidates every active snapshot that admitted it — found via the dependency edges `build_snapshot` writes, matched on the snapshot's own `active_view_refs` — in ONE core transaction with the invalidation-job crash boundary (DURING_CORRECTION_JOB) tripping inside it: a mid-walk crash rolls back the whole revocation and it re-runs. Revocation is idempotent by design (a stale cite can only mean already-revoked — views have no other revision bumps). A queued effect authorized before the revocation holds with STALE_CONTEXT at dispatch revalidation and nothing is sent. Regressions pin the invalidation, idempotence, crash-rollback-and-retry, and the end-to-end dispatch hold. GLM-flash review applied (0 critical/high; transform-chain cascade filed as its own design bead rather than silently resolved).

- Replay acceptance harness (M3 tasks 2.1-2.5, beads hermes-agora-usf.2): `ReplayRunner` grows first-class lifecycle controls — `restart_core()` (durable epoch advance, RUNNING work back to READY, fresh scripted model positioned at the accepted-step count so crashed unaccepted steps replay at the same index), `restart_transport()` (durable generation advance with outbox/attempts continuity), `advance_clock`, `fault_at` — and the manifest gains a validated `faults` plan ({after_event, checkpoint, restart}) applied deterministically: ingest-phase faults re-ingest idempotently, drain-phase faults fire sequentially with the named restart between attempts. Fixture events model upstream edits (same event_id at a new source_revision bumps the fragment record; MESSAGE_DELETED carries no fragments) and the run's final pass reconciles every outbox row past the linearization point through positive world evidence only (INDETERMINATE settles as UNKNOWN). The lease-consume fence is extracted and unit-pinned: stale epoch/generation, expired and already-consumed leases each raise their typed code (I10). The crash-boundary battery covers every named checkpoint with conservative recovery assertions — DISPATCH_STARTED at restart with no world evidence becomes UNKNOWN and its replacement requeue is refused TOO_LATE; a committed world call with a lost receipt reconciles APPLIED to SENT; the correction job is now ONE core transaction (DURING_CORRECTION_JOB trips inside it, so a mid-walk crash rolls back completely and the correction re-runs — never a half-invalidated world). The three handoff §10 stories run end-to-end with restarts — stranger-suggests-research with mid-turn restart continuation, the affordability probe with constrained access and a sidecar crash, r1 reaction held by the edited target, its cancellation crashed mid-flight, and r2 delivered only after the acknowledged cancellation — every story and battery case re-run for byte-identical traces. The I01-I16 matrix maps every invariant to its focused tests (module docstring). GLM-flash review applied (0 critical/high, 3 mediums fixed): fault plans are parse-validated (one fault per event/checkpoint; drain-phase checkpoints require a core restart — the only restart that recovers RUNNING work), ingest faults fire once per event id across edit sequences, never-fired faults are recorded honestly in the trace with a fired flag, recovered ingests are trace-marked, malformed event/revision sequences fail as ManifestError instead of raw store errors, and story 2 asserts the protected probe's non-granted access result from durable records.

### Fixed
